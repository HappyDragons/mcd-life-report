# fixtures/ 目录说明

## ⚠️ 这里的订单数据全部是**合成示例数据**

`orders.json` 是**人工虚构**的演示数据，用于让 `python demo.py` 在不联网、不需要 Token 的
情况下跑通完整链路。它**不是**真实用户的订单，也**不是**实时的 MCP 返回结果。

- 订单号（`SYN-0001` ~ `SYN-0010`）、门店名（`示例门店A（虚构）`）、时间、金额、商品全部为虚构；
- 不代表任何真实用户、真实消费记录或真实价格；
- 真实价格、库存、门店信息请以麦当劳官方渠道的实时结果为准。

## 这个文件为什么正好 10 单

麦当劳 MCP 的 `order-list` **没有分页参数，只返回最近 10 单**。本文件刻意也放 10 单，
用来还原这个窗口限制，并顺带演示两件事：

1. 「累计消费 / 最长连续天数」这类结论的窗口上限就是这 10 单，**不等于人生总和**；
2. 时间轴上会出现「断档后回潮」「末尾倦怠」等长时间跨度的判据，
   而真实用户如果 10 单都集中在两周内，这些阶段就不会出现（这也是诚实的一部分）。

## 数据里刻意埋了哪些边界情况

| 埋点 | 所在订单 | 用途 |
|---|---|---|
| 整单退款 | `SYN-0009`（实付 ¥29.00，退款 ¥29.00） | 验证「整单退款不得计入消费额」，并在图上以空心点标记 |
| 连续两天点单 | `SYN-0006` / `SYN-0007` | 验证「最长连续天数」 |
| 新品类首次出现 | `SYN-0003`（甜品）、`SYN-0005`（咖啡） | 验证「探索期」判据 |
| 断档 ≥ 30 天后归来 | `SYN-0008`（距上一单 48.2 天） | 验证「回潮期」判据 |
| 断档 ≥ 30 天且为最后一单 | `SYN-0010`（距上一单 37.0 天） | 验证「倦怠期」判据 |
| 深夜订单 | `SYN-0005`、`SYN-0009`、`SYN-0010` | 验证「最贵的深夜订单」（22:00–04:59） |
| 单笔最大金额 | `SYN-0004`（¥58.00） | 验证「单笔最大金额」与转折点标注 |

## 字段结构

文件模拟 `order-list` 的返回形态：**外层信封 + 订单数组**。

```json
{
  "_meta": { "synthetic": true, "...": "元信息，适配层会忽略它" },
  "data": { "orders": [ { "orderId": "...", "orderTime": "...", "payAmount": 3950, "refundAmount": 0,
                          "storeName": "...", "orderStatus": "...",
                          "products": [ { "productName": "...", "quantity": 1, "price": 2500, "category": "汉堡" } ] } ] }
}
```

- `payAmount` / `refundAmount` / `price` 的单位是**分**（MCP 侧金额单位即「分」，展示前 ÷100）；
- `orderTime` 为北京时间（`YYYY-MM-DD HH:MM:SS`），适配层也支持带时区的 ISO 8601 与 Unix 时间戳；
- 字段名容错匹配（例如 `payAmount` / `pay_amount` / `actualAmount` 都能识别），
  完整映射表见仓库根目录的 `MCP_INTEGRATION.md`。

## 换成你自己的数据

离线 demo 支持任意同结构的 JSON：

```bash
python demo.py --input /path/to/your-orders.json
```

用真实数据时，请自行确认该文件不会被提交进仓库（`.gitignore` 已默认忽略 `orders*.json`、
`exports/` 与 `out/`）。**不要把真实订单号、手机号、地址写进公开仓库。**
